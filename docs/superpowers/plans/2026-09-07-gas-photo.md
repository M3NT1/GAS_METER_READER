# Gas Photo Implementation Plan

> **For agentic workers:** Use superpowers:subagent-driven-development or superpowers:executing-plans task by task, with failing tests before implementation.

**Goal:** Deliver a Mac photo inbox, reviewed meter readings with exact EXIF capture times, and a installable Home Assistant historical receiver.
**Architecture:** Python service with SQLite outbox and browser UI. A standalone HA custom integration stores exact readings and derives a separate hourly statistic. Network writes are explicit and resumable.
**Tech Stack:** Python 3.12+, FastAPI, Pillow/HEIF, ExifTool when available, httpx, SQLite; Home Assistant 2026.7.2.
**Spec:** `docs/superpowers/specs/2026-09-07-gas-photo-design.md` (approved).

**Implementation status (2026-09-07):** The Mac application, custom Home Assistant receiver, package script and documentation are implemented. Local tests, compilation, package contents, browser smoke test and an isolated Home Assistant 2026.7.2 Recorder roundtrip pass. Production deployment, real-phone acceptance and legacy Energy migration remain deliberate final steps.

## Global constraints

- Xiaomi 15T Pro and iPhone 14 Pro Max. Mac first, portable core.
- Original timestamp with offset and fractional seconds. Missing date/offset blocks acceptance; never file time fallback.
- Original files immutable, SHA-256 deduplication, bounded input and network operations.
- Manual review default; no uncalibrated automatic acceptance, no inferred digits, no fake daily consumption.
- No changes to existing HA energy sources or historical data during development.
- Record wire format: `id` (64 hexadecimal SHA-256), `meter_id` (`gas_main` default), `captured_at` (ISO with offset), `value` (decimal string, m³, up to 3 decimals), `revision` (positive integer), `source` (`manual_review`), optional `metadata` (object).
- HA actions: `gas_photo.import_readings` data `{"readings":[record,...]}`; response contains accepted IDs; `gas_photo.get_readings` returns `{"readings":[...]}`. Both support REST `?return_response`.
- App owns `gasphoto/`, receiver owns `custom_components/gas_photo/`; no cross-runtime import dependency.
